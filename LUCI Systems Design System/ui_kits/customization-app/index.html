AI Customization App · mock-up

Document Studio — three two-pane directions

A mock-up for your developer to see how the AI document-customization app should work. All three are two-pane (selector + chat on the left, live preview on the right) and clickable but static — you can click through the flows, but there is no live AI. They differ in what the left pane leads with.

Variant A

Chat-first

Compact template picker on top, the conversation is the control surface, slim iteration strip above the composer. Minimal chrome — feels like Cursor / v0.

Open A Variant B

Library-first

“My documents” + saved docs up top with a New button, then chat below. Save, reopen, and start-new are front and center — the document library is a first-class citizen.

Open B Variant C

Guided-flow

A step wizard — 1 Pick template → 2 Name client & project → 3 Customize with AI — with a visible iteration/version trail. Best for onboarding and “start a new template.”

Open C

What every variant has

These are the features you asked for, plus the UX pieces a non-UX build usually misses — all present in each direction so you’re comparing layout, not capability.

  • Template selector (all 7: Sales deck, Capabilities, SOW, Budgetary estimate, Proposal — LED / Retrofit / Upgrade)
  • Chat box for customization details + iterative “modify / improve” turns
  • Live preview on the right that updates per iteration
  • Save (writes to this browser so you can reopen), Download PDF, New / start-over
  • Iteration trail — see what changed each turn, step back to an earlier version
  • “What changed” highlight + locked-region respect (the AI only touches editable pages, same rule Mike follows today)
  • Client / project naming, empty states, processing feedback
