## Worldview

Complex environments fail because of **what they accumulate** — vendors, processors, interfaces, workarounds. LUCI’s answer is **subtraction**: a shorter list of things to manage. Complexity is not solved by a better interface.

Lead with the **customer’s problem**. LUCI is the means, not the subject.

Stakes are operational: not optional, non-negotiable, cannot afford failure. The team is permanent: built in, not bolted on; a team that stays.

## Claims

Every objective line needs a basis. Unsubstantiated → do not use.

**Do not wait for or invent:** revenue lift, handle %, payback, guest-sat scores, “90% hardware reduction” (old README — retired).

**Do use:** counts of what LUCI runs (displays, walls, zones, install window, racks removed) when project-true.

Launch / New LUCI: feature list is **not final until Mike signs**. Never name Hub, CoreX, tunnel vendor, correlation IDs. Do not say we replace Q-SYS.

## Social caption rule

LED walls, racks, before/after = **hook**. Caption **closes on the abstraction**: one interface, one map, one team. Write for IT/ops leadership, not technicians. First-person we/our is default for case-study and thought-leadership posts.

No in-progress install photos. Named client only with OK on file.

## Launch message (in flight)

New LUCI = **beta, property by property**, not a splash. Signal may mention it only as beta framing. No launch case study. Control / Automate / Execute. Platform + partnership.

Lead (when Mike’s list is signed): venue panels, staging, audit trails + in-product support, customizable interface — as **capabilities**, not “shipped on this date.”
