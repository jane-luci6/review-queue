# Wave 2 — Checklist: will the next wall join the house?

**Topic:** The next install either lands on what already runs the property, or it starts a second stack.
**Persona:** Prospects about to add a wall, a sportsbook, a room — afraid the new piece is a new system.
**Source:** Sam’s Town (wall on the platform already running) and the consolidation argument. Public proof points at the live case-study pages. Not Aliante. Not a LUCI install how-to.
**CTA:** Book a walkthrough before the next wall is bid as a separate island.

**Cover:**
- Questions before the PO: does this room use the same sources, the same looks, the same people as the rest of the floor? If yes, a second console is the failure.
- Will staff have to relearn it? Will overnight drift now have two places to hide?
- LUCI close: one interface that works with the A/V already there. Does not replace. Does not name partners.
- Optional pointer to Sam’s Town case study as “a wall that joined the house.”

Constraints for every piece
- Readers are new prospects (property A/V, IT, ops leadership). Not a customer LUCI how-to.
- Always write A/V.
- LUCI works with and absorbs the systems already on the floor. It does not replace them. Do not name partners or competitors (no Q-SYS, no brand fight). Never call LUCI a layer.
- New LUCI is beta, property by property. Not a public splash. Do not write “we launched.”
- Do not invent ROI, percentages, or extra stats. Only facts in this brief.
- Never write the word “easy.”
- Institutional voice. Short. LUCI is the means, not the hero speech.
- This is a lead magnet. It has to help before they have LUCI. Close with a walkthrough, not a LUCI procedure.
